# Create Payment Processor

Step-by-step guide to creating and configuring a payment processor for handling payments in your application.

<Callout>
  **What is a payment processor?** It's an intermediary between your application
  and payment systems (Stripe/Paddle) that processes transactions and manages
  subscriptions. [Read mode](/docs-v2/payment-processor/overview)
</Callout>

<Steps>

### Step 1: Creating a New Payment Processor

Navigate to the "Payment Processors" section and click the "New Payment Processor" button.

<div style={{ marginTop: "2rem", marginBottom: "2rem" }}>
  ![Create payment processor](/docs/pp-create.png)
</div>

    <Callout type="warning">
      **Security:** The developer secret key gives access to every product in your Freemius account. It is used only on our servers and is never exposed to buyers.
    </Callout>

    **Connecting a paywall:**

    1. In the Freemius dashboard, create a product for the paywall — one product per paywall.
    2. Open the paywall's **Payment processor manager**, select the Freemius processor and pick the product.
    3. Save. We create a plan with the paywall's monthly, yearly and lifetime prices (plus local prices in currencies Freemius supports), set up the trial and register the webhook in Freemius.

    **Keeping prices in sync:** every time you save the paywall, its prices and trial are pushed to Freemius. Existing subscriptions keep renewing at the price they were bought at. A billing cycle removed from the paywall is removed from the Freemius plan, and a currency removed from the paywall is hidden in Freemius rather than deleted. Don't edit the plan created by monetize.software in the Freemius dashboard — the next sync overwrites it. If a sync fails, buyers are never sent to a Freemius checkout with a different price; use **Sync prices now** in the processor manager to retry.

    **Limitations:**

    - Freemius has no weekly billing cycle and holds one price per cycle, so weekly prices and a second monthly (or yearly) price are sold only through your other processors.
    - Freemius sells in USD, EUR, GBP, CAD, AUD, ILS, PLN, CHF and RSD. Buyers with local prices in other currencies are routed to your other processors; if Freemius is the only processor, they pay the USD price.
    - Disconnecting a paywall keeps the webhook in Freemius, so renewals and cancellations of subscriptions sold on it are still recorded. New Freemius sales of that product outside the paywall are not attributed to it.
    - Offer discounts are applied with a Freemius coupon that we create for each checkout. The coupon works only for the plan and billing cycle being bought, can be redeemed once and expires in 24 hours; the discount also applies to renewals, the same way as on Stripe and Paddle. Coupon codes start with `MSO`: don't edit or delete active ones, and unused expired coupons are deleted automatically. A 100% discount can't be applied through Freemius, so such buyers are routed to your other processors; if Freemius is the only processor, they pay the full price. The same happens if Freemius doesn't respond in time when the coupon is created.

    **Processors created before developer keys** keep working as they are: one product, prices configured by hand. Offer discounts are applied to them with coupons too. Open such a processor and add developer keys to switch it to automatic price sync — its paywall keeps selling while you do it.

After filling in all fields:

1. **Key validation**: The system will automatically verify the correctness of API keys
2. **Webhook creation**: A webhook for event processing will be created automatically
3. **Activation**: The processor will be activated and ready to use

</Steps>

## Troubleshooting

<Accordion>
  <Accordion.Item title="Stripe key validation error">
    Check: - Correctness of copied keys - Key compliance with selected mode
    (test/live) - Access permissions in Stripe account
  </Accordion.Item>

  <Accordion.Item title="Paddle key validation error">
    Make sure that: - API Key is created with "Never Expires" and full
    permissions - Vendor ID contains only numbers - You're using the correct
    environment (sandbox/production)
  </Accordion.Item>

  <Accordion.Item title="Freemius key validation error">
    Make sure that: - You copied the developer keys from My Profile → Keys, not
    the keys of a single product - Developer ID contains only numbers - The
    public key starts with `pk_` and the secret key with `sk_`
  </Accordion.Item>

  <Accordion.Item title="Freemius prices are not synced">
    Open the paywall's payment processor manager and press **Sync prices now**
    to see the exact error. Common causes: - The paywall has only weekly
    prices, which Freemius can't sell - A local price is outside the range
    Freemius allows for that currency - The product was deleted in Freemius or
    belongs to another Freemius developer account
  </Accordion.Item>
</Accordion>
